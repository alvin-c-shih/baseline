Scale and Long Context

The last claim is the biggest: scale is all you need. You'll measure a scaling law on your own machine and see when a smaller model is the better buy. Then you'll follow attention's cost as context grows, from the n² compute and the KV cache to FlashAttention, million-token windows and the linear-time successors, and end with the song's real lesson.

5.1 · 2020–22

Scale is all you need

Make the model 10× bigger and the loss drops by a predictable amount, a pattern that has held over seven orders of magnitude.

A familiar idea first

-O3 for a binary you will run a billion times

Spending longer in the compiler makes no sense for a script you run once and obviously pays for a binary that runs a billion times. Training is the compile; serving is the runs. Chinchilla optimizes the compile alone. If you'll serve heavily, put more training compute into a smaller model.

Loss follows a scaling law, a power law in parameters N, data D and compute. That turned model building into budgeting: predict the loss before paying for the run. The lab fits L = a·N−α + c to your own runs; on a laptop α lands near 0.1.

Chinchilla answered one question: for a fixed training budget, which size and how much data give the lowest loss? About 20 tokens per parameter. But a model is trained once and then run, possibly trillions of times. Training costs about 6ND, and every generated token costs about 2N. A smaller model trained well past the Chinchilla point (overtraining) has a slightly worse loss for the same training budget, and every request it serves is cheaper.

Worked example. Chinchilla-70B on 1.4T tokens: 6 × 70B × 1.4T ≈ 5.9 × 10²³ FLOPs to train. Llama 3 8B on 15T tokens: 6 × 8B × 15T ≈ 7.2 × 10²³, a similar training bill. But each token it generates costs 2 × 8B = 16 GFLOPs instead of 140, about 9× cheaper to serve. At a trillion tokens served per day, the 70B's serving compute equals its entire training cost in about four days.

The math
$$C_{\text{train}}\approx 6ND\qquad C_{\text{serve}}\approx 2N\ \text{per token}\qquad L(N)\approx\Big(\frac{N_c}{N}\Big)^{\alpha_N},\ \alpha_N\approx0.076$$

Back then

Scaling laws turned model building into budgeting: predict the loss before you spend $10M on a run. Chinchilla (2022) showed that most big models, Gopher (280B) included, had been trained on too little data. A 70B model trained on more tokens beat it.

The business side

That's why deployed models are usually "overtrained" small ones. LLaMA (2023) trained 7B on 1T tokens, and Llama 3 8B saw 15T, about 1,900 tokens per parameter. For a popular product serving dominates the bill, and a smaller model also fits on cheaper hardware or a phone. Reasoning models shifted the balance again by spending extra compute at answer time (test-time compute).

Lore

Rich Sutton's 2019 essay "The Bitter Lesson" argued that general methods that scale with compute beat human cleverness every time. The pre-chorus's "scale is all you need" is its four-word summary, and "just add more GPUs" its meme form.

5.2

Attention, quadratic in the length

Double the context and attention's work goes up 4×, and the memory for past tokens keeps growing.

A familiar idea first

All pairs, and memoization

Comparing every item in a list with every other is a nested loop: n² work, so double the list and the work goes up 4×. The KV cache is memoization: keep each past token's keys and values so they're never recomputed, at the cost of memory that grows with history.

Self-attention scores every pair of tokens: n² per head per layer. Generation also keeps a KV cache for every past token. For a 7–8B model at a million tokens, that's over 100 GB.

The math
$$\text{KV bytes}=2\cdot L\cdot h_{kv}\cdot d_{\text{head}}\cdot n\cdot \text{bytes}$$
LAB · notebook §5.2
Back then

Serving long-context models is mostly a memory-management problem. Grouped-query attention, paged KV caches (vLLM) and cache quantization all exist to shrink that one number.

The business side

KV-cache memory decides how many users one GPU can serve at once, so it sets the price of long-context requests. Paged caches (vLLM) and prompt caching are direct cost cuts, and providers charge less for cached input tokens.

Lore

In 2020–21 every month brought an "efficient Transformer": Linformer, Performer, Reformer, Longformer, BigBird. The 2020 survey listing them is titled "Efficient Transformers." Most never displaced plain attention plus FlashAttention.

5.3 · 2022

FlashAttention tiles it in SRAM

Same attention, same numbers. It just never writes the giant score table to slow memory.

A familiar idea first

Tiles and running totals

1 · Matrix multiply in tiles. Each output cell is a row of A dotted with a column of B. Split the rows, the columns and the shared dimension into blocks and add up the block products: same answer, but each block fits in fast cache. CPU math libraries have used this "loop tiling" for decades.

2 · Running totals. You can compute the max or sum of a stream without storing it: keep a running value and update it as items arrive. Softmax needs a row's max (for numerical safety) and its sum before it can normalize, so keep both as running totals, and when a later tile raises the max, rescale what you have so far.

3 · Memory hierarchy. GPU SRAM is to HBM what CPU cache is to RAM: tiny, and an order of magnitude faster.

Attention, for each query row, is three steps: score it against every key, softmax the scores, then take the weighted sum of the values. Done naively, the whole n × n score table is written to the GPU's main memory (HBM) and read back, and for long inputs that traffic, not the arithmetic, is the bottleneck. FlashAttention combines the three ideas above: it works through the keys one tile at a time inside fast SRAM, keeps the softmax's max and sum as running totals (the online softmax), and never stores the table. The lab builds it in about 15 lines and matches naive attention to 10⁻⁷.

The math
$$m\leftarrow\max(m,\max_j s_j),\quad \ell\leftarrow \ell\,e^{m_{\text{old}}-m}+\sum_j e^{s_j-m}$$
LAB · notebook §5.3
Back then

Many papers had cut attention's FLOPs with approximations, yet were often slower in wall-clock time. FlashAttention made the point that on GPUs, moving data costs more than arithmetic.

The business side

Attention time is GPU-hours, and GPU-hours are the main cost of training and serving. FlashAttention went into PyTorch and nearly every LLM stack within about a year, and it made long context windows affordable to sell.

Lore

The community's term for making GPUs fast is "go brrr", from Horace He's essay "Making Deep Learning Go Brrrr From First Principles" (borrowing the money-printer meme). FlashAttention is a canonical brrr.

5.4 · 2020–24

Context: 2K, then a million; a needle in a haystack

Models can now read a million tokens. The question is whether they actually use them.

A familiar idea first

Working memory and a grep test

The context window is the model's working memory: it can only use what fits in it right now. A needle-in-a-haystack test is a grep test: plant a unique string in a long file and check that the model finds it.

The context window grew from 2,048 tokens to a million. A needle in a haystack test hides one fact at some depth and asks for it. The lab sweeps length × depth on your tier's LLM. Passing is necessary, not sufficient: reasoning over a long document is much harder than finding one line.

LAB · notebook §5.4
Back then

"Lost in the Middle" (2023) showed models using the start and end of long contexts much better than the middle. Long-context benchmarks have been getting harder ever since.

The business side

Long context sells: "upload your whole codebase" is a product feature. It's also priced per token, which is why providers discount repeated prompts (prompt caching), and why retrieval, sending only the relevant pages, is often the cheaper design.

Lore

When Anthropic launched a 100K-token context in 2023, it changed one line of The Great Gatsby and had Claude find it. Greg Kamradt's later needle test hid a sentence about eating a sandwich in Dolores Park inside Paul Graham essays, and the heatmaps went viral.

5.5 · 2020–23

A linear-time successor's training up its strength

Keep a fixed-size running memory instead of every past token, and each new token costs the same no matter how long the context.

A familiar idea first

A fixed-size sketch

A running counter or a HyperLogLog keeps a fixed-size summary of a stream instead of the whole log. That's cheap, but it can't answer an exact question about item #4,217. Linear-time models make the same trade: a fixed-size state instead of every past token.

Linear attention, state-space models (S4, Mamba) and RWKV bring back a fixed-size state that trains in parallel. The lab checks chunked linear attention against the O(n²) form and times both. Most current long-context designs are hybrids.

The math
$$S_t=S_{t-1}+\phi(k_t)v_t^\top,\quad o_t=\frac{\phi(q_t)^\top S_t}{\phi(q_t)^\top z_t}$$
LAB · notebook §5.5
Back then

The catch is recall. A fixed-size state can't hold every exact token, so pure linear models struggle to copy and look up, which attention does easily.

The business side

Constant cost per token means long conversations stop getting more expensive per message, and models can run in small memory on devices. That's the commercial pull behind hybrids, which keep a few attention layers for exact recall.

Lore

The 2020 paper behind your linear-attention lab is titled "Transformers are RNNs." The successors are named like a zoo: Mamba, Hyena, RWKV (pronounced "RwaKuv").

5.6

Every "all you need" becomes a footnote

Every state of the art becomes a baseline, and baselines are still worth running.

A familiar idea first

Benchmark against the naïve version

Before shipping a clever cache or algorithm, you time it against the simple version. A baseline is the ML equivalent, and the simple version often wins on cost, latency or maintenance.

Memory (1997), depth (2015), attention (2017), scale (2020): four claims, each a paper with a date. In practice baseline is the most useful word in this course. Before reaching for a large model, build the cheapest thing that could work and measure it on held-out data. On tabular data, gradient-boosted trees still often win.

Back then

Every era in this course believed it had found the answer, and every era was partly right. The parts that survived are the ones that scaled.

The business side

A baseline is also a budget argument. If logistic regression gets 90% of the value at 1% of the serving cost, that's usually the product decision.

Lore

"Related work" is where old champions end up. Schmidhuber has spent years making sure his are listed.

Final project

One more time

Pick your own problem, run a dumb baseline, then try to beat it, honestly.

Use a small dataset you care about: support tickets, commit messages, log lines. Split it, record a baseline, try a few-shot prompt, LoRA-fine-tune if it's worth it, and report all three on the test set once. Put magenta on the winner. Then wait for the next deadline.

LAB · notebook §5.6

Checkpoint

  1. Chinchilla says about 20 tokens per parameter. Why are deployed models usually trained on far more?
    Answer

    Chinchilla minimizes training compute. Serving costs about 2N per token forever, so a smaller, longer-trained model costs a bit more once and much less on every request.

  2. Where does attention's cost grow as n², and where does memory grow as n?
    Answer

    Scoring every pair of tokens is n² per head per layer. The KV cache stores keys and values for every past token: linear in n, and often the memory limit when serving.

  3. FlashAttention computes the same numbers. What does it save?
    Answer

    Memory traffic: it works in tiles inside fast on-chip SRAM with a running max and sum, so the n × n table never goes to main memory.

  4. What does a linear-time model give up for constant cost per token?
    Answer

    Exact recall: a fixed-size state can't keep every past token, so copying or looking up a specific earlier detail gets harder.
